# ARTBACK

Закрытое сообщество ста YouTube-авторов: регистрация только после подтверждения
YouTube-канала, общий групповой чат с настоящим сквозным шифрованием (E2EE),
медиа в S3, ежедневное обновление статистики подписчиков и админ-панель.

Первый подтвердивший канал участник автоматически становится администратором.

---

## Что внутри

- **Регистрация на 100 мест.** Аккаунт можно создать заранее, но участником
  считается только пользователь с подтверждённым YouTube-каналом. Лимит в 100
  участников проверяется транзакционно, гонки исключены.
- **Подтверждение владения каналом.** Два способа:
  1. вставить код `ARTBACK-XXXXXX` в описание канала и нажать «Проверить»;
  2. войти через Google OAuth — канал из аккаунта привяжется автоматически.
- **Настоящее E2EE.** Браузер генерирует пару ключей ECDH P-256. Ключ группы
  (AES-256-GCM) передаётся участникам завёрнутым персонально под их публичный
  ключ. Сервер хранит только шифротекст сообщений и медиа. Приватные ключи
  никогда не покидают браузер.
- **Медиа в S3.** Файлы шифруются в браузере, затем загружаются через сервер в
  приватный S3-бакет. Лимиты: изображения 8 МБ, видео 50 МБ, аудио 15 МБ,
  файлы 10 МБ (настраиваются).
- **Ежедневная статистика.** YouTube API позволяет запросить до 50 каналов за
  один `channels.list`, поэтому для 100 участников нужно **2 запроса в сутки**.
  По умолчанию синхронизация запускается в 03:17 UTC; есть ручная кнопка в
  админке и обновление при старте, если данные старше суток.
- **Каталог авторов.** Аватар, имя канала, @ник, подписчики, дата вступления,
  статус онлайн, бейдж администратора.
- **Администрирование.** Блокировка/разблокировка, назначение и снятие
  администраторов, удаление сообщений, обновление данных канала, ручная
  синхронизация, журнал действий, статистика хранилища.

## Быстрый старт на VPS (одна команда)

Требования:

- VPS с Docker Engine и плагином Docker Compose v2;
- домен, A-запись которого указывает на IP сервера;
- открытые порты **80** и **443** (TCP, а также UDP 443 для HTTP/3);
- YouTube Data API key;
- S3-совместимое хранилище (AWS S3, Cloudflare R2, MinIO и т.д.).

```bash
cd artback
./deploy.sh
```

Скрипт спросит домен, ключ YouTube API и параметры S3, сгенерирует пароли,
создаст `.env`, соберёт образы и запустит контейнеры. Caddy автоматически
выпустит HTTPS-сертификат.

Если `.env` уже создан, `./deploy.sh` просто пересоберёт и перезапустит стек.

### Ручной вариант

```bash
cp .env.example .env
nano .env          # заполните DOMAIN, APP_URL, SITE_ADDRESS, секреты, API-ключи, S3
docker compose up -d --build
docker compose ps
```

После запуска откройте `https://ваш-домен`. Зарегистрируйтесь, привяжите канал —
и вы станете первым администратором.

### Обновление

```bash
git pull            # или замените файлы
docker compose up -d --build
```

### Остановка

```bash
docker compose down          # данные в Docker volumes сохраняются
docker compose down -v       # удалить также БД и сертификаты
```

## Настройка YouTube Data API

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. Создайте проект (или выберите существующий).
3. **APIs & Services → Library → YouTube Data API v3 → Enable**.
4. **APIs & Services → Credentials → Create credentials → API key**.
5. Скопируйте ключ в `YOUTUBE_API_KEY`.

Рекомендуется ограничить ключ:

- Application restrictions: **IP addresses** — публичный IP вашего VPS;
- API restrictions: только **YouTube Data API v3**.

Квота по умолчанию — 10 000 единиц в сутки. Ежедневная синхронизация 100
каналов стоит 2 единицы (`channels.list` — 1 единица за запрос, до 50 ID в
запросе). Поиск канала по названию при привязке использует `search.list`
(100 единиц) и применяется только как fallback, если ссылку/@ник распознать не
удалось. При массовой привязке лучше давать участникам ссылку вида
`https://youtube.com/@handle` или ID канала.

> Канал может скрывать число подписчиков. Это не мешает регистрации: в каталоге
> будет отображаться «скрыто».

## Настройка Google OAuth (необязательно)

Если заполнить `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`, на сайте появится
кнопка «Продолжить с Google». При входе канал привязывается автоматически.

1. В Google Cloud Console: **APIs & Services → OAuth consent screen**.
   Заполните название, support email, добавьте себя в тестовые пользователи
   (или опубликуйте приложение).
2. **Credentials → Create credentials → OAuth client ID → Web application**.
3. Authorized redirect URI:

   ```text
   https://ваш-домен/api/auth/google/callback
   ```

   Для локального запуска: `http://localhost:3000/api/auth/google/callback`.
4. Включите **YouTube Data API v3** (нужен scope `youtube.readonly`).
5. Заполните `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` в `.env` и перезапустите:

   ```bash
   docker compose up -d
   ```

Если у Google-аккаунта нет канала, пользователь попадёт на обычную привязку
канала кодом.

## Настройка S3

Приложение работает с любым S3-совместимым хранилищем. CORS **не нужен**:
браузер загружает и скачивает файлы через сервер, а не напрямую в S3.

Переменные:

```env
S3_ENDPOINT=https://s3.eu-central-1.amazonaws.com   # для AWS можно оставить пустым
S3_REGION=eu-central-1                              # для R2 обычно auto
S3_BUCKET=artback-media
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_FORCE_PATH_STYLE=false                           # true для MinIO и части провайдеров
```

Примеры:

- **AWS S3:** `S3_ENDPOINT` пустой, `S3_REGION=eu-central-1`, `S3_FORCE_PATH_STYLE=false`.
- **Cloudflare R2:** `S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com`,
  `S3_REGION=auto`, `S3_FORCE_PATH_STYLE=false`.
- **MinIO:** `S3_ENDPOINT=https://minio.example.com`, `S3_FORCE_PATH_STYLE=true`.

Бакет должен быть **приватным**. Если у ключа есть право `s3:CreateBucket`,
приложение создаст его при старте; иначе создайте бакет вручную.

Минимальная политика (замените имя бакета):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::artback-media"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::artback-media/*"
    }
  ]
}
```

`ListBucket` нужен для проверки существования бакета. Если хотите, чтобы
приложение создавало бакет само, добавьте `s3:CreateBucket` на `arn:aws:s3:::*`
(или создайте бакет заранее и не давайте это право).

Лимиты задаются в `.env`:

```env
MAX_IMAGE_MB=8
MAX_VIDEO_MB=50
MAX_AUDIO_MB=15
MAX_FILE_MB=10
```

Лимит проверяется и в браузере, и на сервере. Caddy ограничивает тело запроса
60 МБ; если увеличиваете `MAX_VIDEO_MB`, поднимите `max_size` в `Caddyfile`.

## Как устроено шифрование

1. **Ключ устройства.** При первом открытии чата браузер генерирует пару
   ECDH P-256. Приватный ключ сохраняется в `localStorage` этого браузера и
   никуда не отправляется. Публичный ключ публикуется на сервере.
2. **Ключ группы.** Самый первый участник генерирует случайный 256-битный ключ
   AES-GCM. Для каждого нового участника любой участник, у которого уже есть
   ключ, заворачивает его через ECDH + HKDF + AES-GCM под публичный ключ
   получателя. Сервер хранит только завёрнутый блоб и не может его открыть.
3. **Сообщения.** Текст и метаданные вложений шифруются в браузере AES-256-GCM;
   сервер сохраняет `ciphertext` и `iv`.
4. **Медиа.** Для каждого файла генерируется отдельный AES-256-GCM ключ. Файл
   шифруется до загрузки; ключ и IV попадают внутрь зашифрованного сообщения.
   В S3 лежит только шифротекст. Скачивание доступно только авторизованным
   участникам, но и без этого файлы бесполезны без ключа.
5. **Новый участник.** После подтверждения канала его браузер публикует
   публичный ключ. Любой онлайн-участник с ключом группы автоматически
   отправляет ему завёрнутый ключ. Если никто не онлайн, доступ появится, когда
   кто-то с ключом зайдёт в чат.
6. **Бэкап.** В профиле можно скачать JSON с приватным ключом и ключом группы.
   Это единственный способ восстановить доступ к истории на новом устройстве.

### Честные ограничения E2EE

- Сервер видит метаданные: кто, когда, размер сообщения, тип и размер файла.
- Сервер раздаёт публичные ключи участников. Если сервер считается
  недоверенным, отпечатки ключей нужно сверять по независимому каналу — иначе
  возможна подмена ключа при доставке. Имена файлов серверу не передаются:
  они лежат внутри зашифрованного сообщения.
- Нет forward secrecy и автоматической ротации ключа при блокировке участника:
  заблокированный теряет сессию, но если он успел сохранить ключ, теоретически
  сможет расшифровать перехваченный шифротекст. Для полноценной ротации нужен
  протокол уровня MLS.
- Приватный ключ хранится в `localStorage`. Строгий CSP и экранирование React
  снижают риск XSS, но при компрометации браузера ключи могут быть украдены.
- Если все участники потеряют ключ группы и резервные копии, старую историю
  восстановить нельзя. Это свойство E2EE, а не ошибка.
- Регистрация подтверждает владение каналом, но не гарантирует, что за каналом
  стоит тот же человек, что и за аккаунтом, — это ответственность приглашённых.

## Администрирование

Первый подтверждённый участник получает роль администратора. Дальше админы
могут назначать других админов.

В админке доступно:

- статистика: места, ожидающие, заблокированные, онлайн, сообщения, объём S3;
- ручная синхронизация подписчиков (с отчётом: каналов / запросов / обновлено);
- список аккаунтов с email, каналом, статусом, кодом текущей верификации;
- блокировка с причиной и разблокировка;
- назначение/снятие администратора (нельзя снять последнего);
- обновление данных конкретного канала;
- журнал действий;
- удаление любых сообщений в чате.

Заблокированный участник теряет сессии и сокет-соединения, его ключ группы
удаляется. Канал остаётся привязанным, чтобы нельзя было перерегистрироваться
с тем же каналом. При разблокировке место проверяется заново: если все 100
мест заняты, разблокировка отклоняется.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DOMAIN` | Домен без протокола | — |
| `SITE_ADDRESS` | Адрес для Caddy (`domain` или `:80`) | `:80` |
| `APP_URL` | Публичный URL приложения | `http://localhost:3000` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | PostgreSQL | `artback` |
| `SESSION_SECRET` | Секрет сессий | генерируется |
| `YOUTUBE_API_KEY` | YouTube Data API v3 | — |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth | выключено |
| `S3_ENDPOINT` / `S3_REGION` / `S3_BUCKET` | S3 | — |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | S3 credentials | — |
| `S3_FORCE_PATH_STYLE` | Path-style для MinIO | `false` / `true` при endpoint |
| `MAX_MEMBERS` | Лимит участников | `100` |
| `MAX_IMAGE_MB` / `MAX_VIDEO_MB` / `MAX_AUDIO_MB` / `MAX_FILE_MB` | Лимиты медиа | 8 / 50 / 15 / 10 |
| `SYNC_CRON` | Расписание синхронизации (UTC) | `17 3 * * *` |
| `VERIFICATION_TTL_HOURS` | Срок жизни кода привязки | `168` |

`.env` содержит секреты — не коммитьте его. `deploy.sh` выставляет права `600`.

## Диагностика

**«Код не найден в описании канала»**  
YouTube обновляет описание не мгновенно. Подождите 1–2 минуты и нажмите
«Проверить» ещё раз. Убедитесь, что код вставлен целиком (включая `ARTBACK-`) и
канал сохранён.

**«Все 100 мест заняты»**  
Участником считается только подтверждённый канал. Если админ заблокирует
участника, место освободится и регистрация снова откроется.

**«Квота YouTube API исчерпана»**  
Проверьте квоту в Google Cloud. Помните, что `search.list` стоит 100 единиц;
давайте участникам прямые ссылки на каналы.

**«Ожидаем ключ шифрования»**  
Нужен хотя бы один участник с ключом группы онлайн. Обычно это первый админ.
Попросите его открыть чат; ключ передастся автоматически. Если ключ утерян у
всех, восстановите резервные копии из профилей.

**«Не удалось сохранить файл в S3»**  
Проверьте endpoint, регион, bucket, права `ListBucket/GetObject/PutObject/
DeleteObject`, а также `S3_FORCE_PATH_STYLE` для MinIO. Для AWS endpoint должен
быть пустым.

**Caddy не выпускает сертификат**  
Проверьте A-запись домена, доступность портов 80/443 и логи:
`docker compose logs caddy`. Для выпуска сертификата домен должен уже
указывать на сервер.

**`redirect_uri_mismatch` в Google**  
Redirect URI в Google Cloud должен в точности совпадать с
`APP_URL/api/auth/google/callback`.

**Вход по email работает, Google — нет**  
Проверьте, что включён YouTube Data API v3 и заполнены оба параметра
`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, затем перезапустите app.

## Ограничения текущей версии

- Нет подтверждения email, восстановления пароля и 2FA.
- Нет личных сообщений, веток, реакций и редактирования сообщений.
- Нет автоматической ротации ключа группы при блокировке (см. ограничения E2EE).
- Удаление аккаунта не предусмотрено; участника можно заблокировать.
- Один S3-бакет; квоты на объём хранилища на пользователя не заданы.

Эти функции можно добавить без изменения базовой архитектуры.
